# Luna Worker 部署提示词

请建立或更新个人级 Codex 自定义 Agent `~/.codex/agents/luna-worker.toml`。先检查当前安装版本支持的 TOML 格式，并使用以下配置。

```toml
name = "luna_worker"
model = "gpt-6.1-terra"
model_reasoning_effort = "medium"
```

补充清楚的 `description` 和 `developer_instructions`。保留指定模型和推理等级。如果当前版本不支持，报告具体的兼容性问题，未经授权不替换模型或调整推理等级。

## 职责分工

- 当前会话选择的模型作为主 Agent，负责需求理解、计划、决策、任务派发、结果整合和最终验收。准确性优先。
- `luna_worker` 只执行主 Agent 明确下发、边界清楚且可独立完成的任务，例如定向文件搜索、资料整理、运行既有测试、结果摘要和小型授权修改。目标与授权明确时直接执行，未授权写入时保持只读。
- `luna_worker` 不改变整体目标、不扩大范围、不创建其他子 Agent。遇到架构、产品方向、授权或任务边界问题时，停止受影响的操作，向主 Agent 报告证据和待决策项。其他独立且已授权的工作可以继续。
- 按任务需要读取文件，复用现有工具、测试和项目约定。按影响范围做最小充分验证，避免重复调查和重复检查。汇报结果、关键证据及未验证事项。

## 主 Agent 委派规则

先确认实际生效的个人级 canonical `AGENTS.md` 的位置和现有内容，再将以下规则合并进去。复用等效规则，消除直接冲突，避免重复。

1. **按需委派。** 仅在独立任务的委派能节省时间或提高质量时使用 `luna_worker`。简单修改、紧密共享状态或需要连续决策的工作由主 Agent 直接完成。
2. **优先复用。** 同一模块或问题的连续工作优先复用当前任务中可访问且上下文适用的实例。交接时补充变化，按需核对当前文件、版本及测试基线。
3. **合理新建。** 有独立并行工作、需要独立审查、原实例不可用，或旧上下文过长、过时或不适用时，再新建实例。独立审查由未参与该改动的代理或主 Agent 执行。实现者的自测不能替代独立审查。
4. **完整交接。** 每次委派明确目标、必要文件、已有结论和检查、允许修改的范围、预期输出及验收标准。优先交付完整任务，避免细碎指令、重复调查和复制无关历史。
5. **避免重复和冲突。** 并行修改采用互不重叠的写入范围，有依赖的工作顺序执行。子 Agent 执行时，主 Agent 推进其他独立工作，确需结果时再等待，避免频繁催问和无变化轮询。
6. **精简汇报和验证。** 子 Agent 简报结果、修改文件、关键证据、检查结果和未解决事项。主 Agent 按目标和风险验收，复用可靠测试及夹具，只因新改动、新失败、证据不足或必要的独立复核而补测。
7. **及时收尾。** 有明确后续用途时保留实例，否则在工作流结束后关闭。跨会话通过项目文件和简洁的交接记录延续事实，不假定旧实例永久可用。

## 修改范围

- 仅修改 `luna-worker.toml` 和个人级 canonical `AGENTS.md` 中与上述规则直接相关的内容。
- 保留其他配置、无关规则和用户改动。在现有 `AGENTS.md` 中做增量合并。若存在 `CLAUDE.md`，保留其兼容入口用途，规则正文仅维护在 `AGENTS.md`。

## 验证与交付

1. 报告本机 Codex 版本，核对配置格式、模型和推理等级的支持情况。
2. 展示 `luna-worker.toml` 完整内容及本次全部修改的 diff。
3. 使用 TOML 解析器验证文件语法、必填字段及指定值。
4. 使用当前版本支持的方式检查运行时是否识别 `luna_worker`。需要实际调用时，使用最小的只读验证任务，通过指定自定义角色启动。
5. 分别报告文件存在、TOML 解析成功、运行时识别、实际使用指定配置的证据。显示名称和代理自述不能单独证实实际使用的模型和推理等级。无法验证的项目如实说明。
6. 说明规则对新任务、已有任务和已运行子 Agent 的生效范围。按实际观测说明刷新情况。
7. 确认修改未超出范围，清理本次产生且不再需要的临时文件。
